# Security policy

Trindle crash reports is a small project. This page says what you can expect, without promising more than that.

## Supported versions

Only the latest release is supported. A fix goes into the next release and you are expected to update.

| Version | Supported |
|---|---|
| 1.1.1 | yes |

## Reporting a vulnerability

Please do not put the details of a security problem in a public issue. A public report tells everyone, including people running an unfixed copy, before a fix exists.

Use GitHub's private vulnerability reporting on this repository: open **Security**, then **Report a vulnerability**. Only the maintainers can see it.

If you would rather not use GitHub, write to <crash-reports@trindle.org> with "Crash reports security" in the subject. Say what you found, how to repeat it, and which version you used.

## What to expect

You will get a reply. A fix comes as soon as it can be made and checked, and you will be told when it is out. Credit is given if you want it.

Faults that are not security problems can go on the usual bug route in [CONTRIBUTING.md](CONTRIBUTING.md).
